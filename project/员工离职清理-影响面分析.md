清理方式有两种，影响面差别很大：

- **改 `genacti = 'N'`（停用）** —— 推荐。字段值保留，所有主档仍指向原编号，只是不再出现在选择窗、报工、签核等流程中。**风险最小**。

## 五、`gen01` vs `zx01`：为什么这个区分重要

| | `gen_file` | `zx_file` |
|---|---|---|
| 主键 | `gen01` 员工编号 | `zx01` 登录用户 |
| 语义 | 人（可离职） | 账号（随人走） |
| 维护作业 | `arti200` 员工资料维护 | `apci060` POS 用户资料维护 |
| 清理离职影响 | **主档会指向已离职的人** | 账号随人停用，业务中断 |

**关键结论**：`zx_file.zx01` 只在 `tiptop/lib`（`cl_user`、`cl_setup` 等公用函数）、`tiptop/ghr`、`tiptop/azz` 里出现，是登录态；**所有业务档案上的人员字段都指向 `gen_file.gen01`**，不是 `zx_file.zx01`。

所以清理离职时，`zx_file` 停用登录即可，**真正要维护的是各业务主档上的 `gen01` 字段**。

## 六、执行建议

### 6.1 优先用「停用」代替「删除」

在 `arti200` 把离职员工的 `genacti` 设为 `N`，而非删除记录。主档上已存的编号仍能 `SELECT gen02` 取到姓名（历史单据、报表不会显示空白），同时新单据的签核、报工、选窗不会再选到离职员工。

**只有确定主档上已无任何引用时，才考虑改编号或删记录。**

### 6.2 检查顺序

对每个待清理员工，先跑查询找出主档引用：

```sql
-- 客户主档 occ04（示例）
SELECT occ01, occ02, occ04 FROM occ_file WHERE occ04 = 'E1234';

-- 固定资产保管人 faj19（示例）
SELECT faj01, faj02, faj19 FROM faj_file WHERE faj19 = 'E1234';
```

各表字段见附表 A，逐表替换表名/字段名即可。

### 6.3 需要重点确认的主档

优先处理这几张表 —— 它们直接影响日常流程：

1. **`occ_file.occ04`** 客户业务员 —— 离职后该客户无人跟单，所有下单/出货作业的默认业务员会指向无效人员
2. **`ima_file.ima23` / `ima43`** 料件仓管员 / 采购员 —— 离职后该料件的收发料、采购流程无人可接
3. **`faj_file.faj19`** 固定资产保管人 —— 离职后该资产盘点、折旧归属无人
4. **`aba_file.aba36/37/38`** 出纳 / 审核 / 记账人员 —— 影响财务签核权限
5. **`pja_file.pja08`** 项目员工代号 —— 影响工时归集与项目成本

### 6.4 单据档不要动

附表 B 的 148 张表是交易留痕。改了会让历史报表、审计追溯失真。离职员工的单据上保留原编号是正确做法。

### 6.5 附表 C 需人工确认

附表 C 的 19 个字段，代码注释标为人员，但扫描中未发现 `gen01` 校验 —— 可能是：

- 该字段存的是姓名文本而非编号（如 `bol02`「员工姓名」、`gen02`、`ima02`、`sga02`、`oqw02`、`azi02`）
- 或校验写在动态 SQL 里，静态扫不到

清理前建议逐个进数据库确认字段长度与内容形态。

## 七、扫描方法与局限

**识别「gen01 类字段」的判据**（满足任一）：

1. 源码中出现 `gen01 = <某字段>` 的 SQL 比较 —— 强证据，说明该字段存员工编号
2. 字段声明行注释含人员关键词（员工/人员/业务员/保管人/承办人…）—— 弱证据，归入附表 C

**识别「主档」的判据**：该表被某个第 4 字母为 `i` 的作业（`xxxi***`，TIPTOP 的输入/维护类）直接 `INSERT`/`UPDATE`，且作业名含「主檔/基本資料/維護/建立/設定」。

**局限**：

- 动态 SQL（`g_forupd_sql` 字符串拼接）中拼接的 `gen01` 校验可能漏扫
- 部分字段经由 `s_xxx` 子程序间接校验，已通过子程序名回溯但无法完全还原上下文
- 仅覆盖 `.4gl`；`.form` / `.per` / 数据库 schema 未纳入（仓库中无 `.sch` 字典文件）
- 未连接数据库（`192.168.1.19` ssh key 在本机不可用），字段的实际数据分布需在库上确认
